# 具身产业库

记录**哪些公司在用什么技术栈、什么时间做了什么事**的公开数据库。覆盖全球，中文优先。

只收集可核查的事实并按时间排列。**不做推断、不打分、不排名**——谁选对了、谁更可能活下来，由使用数据的人自己判断。

> **当前状态：V0.1，数据集刚起步。** schema、受控词表、门禁与入库工具已可用并有测试覆盖；`events/` 还在积累中。
> 这个库的规矩是每条事实都要有来源链接和页面快照，所以宁可慢，不先堆量。

## 只做三件事

产业名录和「产品发布／融资」时间线已经有人做得很好，本库不重复，收窄到三件它们没做的：

**技术栈可对比、收敛可观测。** 受控词表把技术与商业选择压成固定轴，历史取值不删，同一条轴上所有主体的取值可按时间铺开——分散度下降就是收敛。产品字段写成自由文本就做不到这件事。

**商业信号。** 招投标、部署交付、公开定价、招聘信号、交付形态、目标场景。这一层同类库明确不收。

**结构化与可核查。** 事件是机器可查的 YAML 而不是 markdown 表格，带 lint 门禁、编译视图和来源快照。链接会死，快照不会。

## 收录边界

一条成员规则，不是列举：**以通用机器人本体为最终载体的技术与商业主体**。

整机本体、运控与小脑、具身基础模型、数据采集与供给、仿真与工具链、关键部件、动作与节目内容、系统集成、场景运营都在内；纯工业机械臂、AGV、无人机、扫地机在外。

## 怎么读

| 目录 | 内容 |
|---|---|
| `registry/orgs/` | 主体身份：名字、别名、成立年份、总部、产业层 |
| `registry/datasets/` | 数据集身份：规模、模态、许可、开放程度 |
| `events/` | 事实层。每条事件带日期、精度、来源链接、快照、佐证状态 |
| `vocab/` | 受控词表。11 条轴的全部合法取值 |
| `build/` | 编译产物：主体页、数据集页、合并 JSON |

主体页是**算出来的**，不是写出来的。页面上每条事实都标着来源事件 id，可以一路追到原始链接。

## 几条不能破的规矩

**每条事件必须有可访问的来源链接、抓取日期和页面快照。** 链接会死、通稿会改、官网会悄悄改参数。没有快照，两年后整个库就是一堆无法验证的断言。

**技术栈只能用词表里的取值。** 自由文本能存信息但无法横向对比，而可对比性是本库唯一比新闻聚合强的地方。

**技术栈的历史取值不删。** 一家公司从 MuJoCo 换到 Isaac Lab，两条都留着，各带生效时间和来源。把所有主体在同一条轴上的取值按时间铺开，才能看出哪条轴在收敛、哪条还在打。

**正文不许出现推断性措辞。** 「预计」「大概率」「可能是因为」这类词由 lint 拦截。中立不靠自觉，靠机器强制。

**选型理由只以官方表态记录。** 公司为什么选某条路线，几乎没有第三方客观记录，但它们自己会在发布会和技术博客里说。本库只记「谁在什么时候这么说过」。

## 用法

```bash
make setup         # 建 venv 装依赖，换机器后第一步
make lint          # 门禁
make lint-strict   # 发布前门禁，事件不足 3 条的主体也算失败
make build         # 编译主体页与数据集页到 build/
make test          # 合规夹具必须过，违规夹具必须被拒
make test-ingest   # 微信解析器测试，不打网络
make serve         # 入库后台，默认 http://127.0.0.1:8790
```

需要 Python 3.11+ 和 `uv`。绑定地址可用 `EID_HOST` / `EID_PORT` 覆盖。

## 换机器

整个库是自包含的，没有写死任何机器相关路径。`.venv/`、`build/`、`drafts/` 都不进 git，可重建。

```bash
git clone <remote> && cd embodied-industry-db
make setup && make lint && make serve
```

**快照进 git**，所以证据跟着数据一起走，换机器不丢。待审草稿不进 git——它们是临时状态，换机器前记得先审完或丢弃。

## 收录深度

全覆盖不等于全深度。主体分三档：

- `stub` — 仅身份信息，事件不足 3 条，不进公开索引
- `draft` — 3 条以上带来源事件
- `complete` — 主要轴有取值且事件覆盖近 12 个月

一个只有三行的条目，只要每行都有日期和来源链接，它就是有用的。写得很长但没出处的才是垃圾。**质量按可核查密度算，不按篇幅算。**

技术定义在第一个库，产业名录与发布融资时间线在第二个库，本库做技术栈收敛、商业信号和结构化可核查这三件它们没做的事。
